# Отчет по K3-01: CI/CD и ветки
# 1 Схема  
1) делаем fork репозитория (копируем) -> 
2) создаем ветку для прохождения практической работы -> 
3) пушим проект -> 
4) делаем пулл из рабочей ветку в ветку main -> 
5) после всего гит автоматом запускает проверку 

# 2 Сравнение 
GIT-flow создан для больших компаний. Там есть все ветки - для разработчиков, для подготовки релиза, для быстрых правок. Слишком много разных направлений, которые очень то и не нужны для обычного студента. Поэтому мы используем в виде нашей схемы, которую я составил выше. 

# 3 Различия
CI - автоматическая сборка проекта и прогон тестов при каждом изменении кода. Оно проверяет ошибки на раннем этапе в пулле.
Continuous Delivery - готовность кода к выкатке на любой этап в любой момент времени, но только после прохождения тестов.
Continuous Deployment - автоматический выпуск и развертывание приложения на продакшен без участия человека. 

# 4 Обратная связь 
Скорее всего первая обратная связь об ошибке появиться на этапе пулла. Он может подсветить например упавший тест.
